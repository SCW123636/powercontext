要解决的问题

练完车，数据在，结论没了

车队每场下来几十个遥测文件。前三件事每次都在重复，第四件事从来没人做。

① 手算圈速与分段

打开 CSV、对齐时间轴、切分段，算出哪一圈更快。一个上午就没了。

② 逐弯找损失

刹车点、apex、出弯速度要一个个弯比对，肉眼扫图表，容易漏掉真正吃亏的弯。

③ 结论靠人记

「上次 C6 慢了」写在聊天记录里。换人接手、隔一周再来，等于重新开始。

LapCoach 的取舍：计算交给命令，记忆交给 PowerContext。一次 ingest 同时完成两件事，下一次 ingest 先把上一次的结论读出来。

核心功能

一条命令，三步都做完

01

遥测解析

自动识别时间、距离、速度、油门、刹车、挡位、GPS 列，兼容 km/h、mph、m/s 与逗号小数；按圈号或时间间隔分圈。

02

逐弯对比

找出最快圈，与参考圈对齐每个弯的刹车点、apex 速度、出弯速度与分段耗时，直接指出最亏的三个弯。

03

记忆复用

结论写成 measurement 与 observation 两类记忆，按车手隔离；下次同赛道自动检索并给出逐弯进步。

记忆是怎么工作的

PowerContext 在这里不是装饰

去掉它，「下次自动带出上次结论」和「按问题检索历史」两个功能都不存在。

  1. ingest

    解析 CSV，算最快圈与最亏弯。

  2. 写记忆

    人读一句结论 + 一行机器可解析的字段，写入该车手的 Scope。

  3. 下次先检索

    同赛道的历史 measurement 被命中，逐弯 apex 变化算出来。

  4. ask

    按问题检索条目，返回 entry_id + revision，并组装可交给模型的上下文。

运行方式

评审在本机五分钟跑通

只需要 Python 3.11+ 与 uv。PowerContext Server 由 CLI 在进程内拉起，数据落 SQLite，不用另开服务。

三条命令

cd qoder
uv sync
uv run lapcoach ingest samples/two_laps.csv --driver alex --track Zandvoort
uv run lapcoach ask "C6 上我上次损失了多少时间" --driver alex

换一份第二天的 CSV 再 ingest 一次，就能看到「记忆复用」段落。

技术栈

  • PowerContext 1.2.0：车手 Scope、memory entry、FTS 检索、prepare_context
  • 遥测引擎：纯标准库解析与弯道识别，复用本队魔搭 Skill 中验证过的实现
  • CLI：ingest / ask，支持 --json

也支持 LAPCOACH_POWERCONTEXT_URL 指向已运行的外部 Server。
