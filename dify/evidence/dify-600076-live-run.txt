## 已知限制与判题侧说明

1. **Dify 1.4 的 HTTP 节点 json body 只能有一个 data item**，其值是一段 JSON 模板字符串（`core/workflow/nodes/http_request/executor.py` 里先 convert_template 再 json.loads）。仓库里的 DSL 已按此改写；后果是正文里的双引号会破坏 JSON，演示文案全部使用中文标点规避。更稳的写法是在 HTTP 节点前插入 code 节点用 json.dumps 生成 payload，本次未采用（保持 DSL 在 1.4 上零依赖可导入）。
2. **写入正文用「；」代替换行**，原因同上（JSON 字符串里 `\n` 会被模板转义链吃掉）。
3. **Docker 内访问宿主 PowerContext**：api/worker 需要 `extra_hosts: host.docker.internal:host-gateway`，**ssrf_proxy 也必须加**，否则 HTTP 节点经 squid 出站时 DNS 解析不到 host.docker.internal，报 `Reached maximum retries (0)`。
4. **PowerContext 的 memory 抽取是后台异步的**（`RUNTIME_SCHEDULE_SECONDS=20`），写入 source 后要等抽取完成才能被下一场召回；抽取期间若模型调用抖动会记 `Artifact processing failed` 并自动重试，本次出现过几次瞬时失败，重启后同一批 source 全部抽取成功。
5. 证据里的 `probe-1` source（后轮倾角 2.5→3.2 度）是我为验证抽取链路单独写入的对照 source，其记忆条目已在采集完成后 retire，不属于演示脚本内容。
